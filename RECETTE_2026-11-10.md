# Recette du circuit interne du 10 novembre 2026

La recette locale du circuit interne est réussie : 31 contrôles HTTP métier, 159 tests Java sans échec ni test ignoré, construction de production du frontend, TypeScript et lint réussis. Les contrôles navigateur portent sur cinq pages, les champs du refus de facture et une soumission du formulaire de routage. Ils ne constituent pas une réception de toutes les interfaces externes ni une certification intégrale du cahier des charges.

Le périmètre convenu exclut la gateway de paiement, les nouvelles API SITAX et les notifications externes, dont les contrats ou fournisseurs ne sont pas encore disponibles. Les imports FACNO et l’extraction OCR utilisent des données synthétiques dans cette recette. Le contrat Java vers l’application Flask livrée est testé séparément, avec les fournisseurs Mistral/OpenAI simulés et sans appel payant.

## Corrections livrées

- Les données du vendeur sont conservées pendant l’attente d’une réponse DGI et après confirmation du refus. La même confirmation est rejouable sans deuxième décision.
- Les points d’un constat crédité ne peuvent pas être remplacés sans correction tracée. Une infirmation ferme le constat, annule les mouvements nécessaires et interdit son recrédit. Les primes déjà payées ne sont pas retirées automatiquement.
- Les crédits concurrents sont sérialisés pour appliquer les limites sans double crédit. Les dépôts hors période admissible sont refusés.
- L’identité d’un bénéficiaire doit être vérifiée avant l’approbation d’une prime. Un même dossier vérifié rattache les comptes de cette personne, sans fusion des comptes FACNO ni rapprochement automatique sur le téléphone. Le plafond est contrôlé sur les montants approuvés ou payés, tous comptes rattachés et versions confondus, sous verrou transactionnel.
- Les règles sont choisies selon la date du dépôt, avec conservation des versions des crédits historiques. La revue des primes et les coordonnées de paiement ne sont plus limitées à la version initiale.
- Les courriers sont regroupés par service à partir du routage NIF/service. Leur préparation hebdomadaire est rejouable ; l’envoi dispose d’une date et d’une référence de bordereau. Un courrier validé mais non envoyé n’est pas compté comme transmis.
- Le tirage utilise l’identité vérifiée pour garantir un seul lot par personne parmi les comptes rattachés. La liste ordonnée des éligibles et la graine sont conservées. Le tirage final ne peut pas être exécuté avant avril 2027.
- Un réexamen ne peut être marqué modifié sans nouvelle qualification effectivement enregistrée après la demande.
- Le budget prévisionnel est historisé. Les rapports hebdomadaires et mensuels clos sont archivés avec leurs chiffres et le budget connu à leur génération, sans écrasement lors d’un rejeu.
- Les erreurs de lint ont été corrigées. Les sorties de construction et de recette disposent de répertoires séparés et exclus de Git/ESLint.

## Reproduire la recette

Docker et les services PostgreSQL/Redis de développement doivent être démarrés. Les bibliothèques Python sont celles de `../ocr-flask-coolify/requirements.txt`. Utiliser son environnement virtuel, ou un environnement Python de test équivalent. Le port 8081 doit être libre.

```bash
# Depuis backend, premier terminal : Flask livré, fournisseurs uniquement simulés
../ocr-flask-coolify/.venv/bin/python scripts/serve-herdys-contract.py ../ocr-flask-coolify/app.py --port 5002

# Deuxième terminal : toutes les vérifications Java, puis recette HTTP isolée
./mvnw clean verify -Dherdys.contract.url=http://127.0.0.1:5002/ocr
../ocr-flask-coolify/.venv/bin/python scripts/recette.py
```

Le script crée une base `signalements_recette_*` distincte et un espace de sessions Redis distinct. Il conserve la base pour inspection et arrête son backend à la fin. Ajouter `--keep-running` pour vérifier l’interface sur `BACKEND_URL=http://localhost:8081 NEXT_DIST_DIR=.next-recette bun run dev --port 3001`, depuis le frontend. Les identifiants synthétiques aléatoires sont enregistrés dans `/tmp/tombola-recette/runtime.json`, avec accès restreint ; ils ne doivent pas être versionnés. Les résultats et journaux sont dans `/tmp/tombola-recette/`.

## Mise en service et étapes humaines

Dans Situation du déclarant, le superviseur vérifie les justificatifs et rattache tous les comptes connus d’une même personne à la même référence de dossier. Ce rattachement est définitif dans l’interface pour empêcher une remise à zéro du plafond. Une erreur de rattachement nécessite une procédure administrative contrôlée ; aucune fusion automatique par téléphone n’est appliquée.

Dans Courriers, renseigner le service de chaque NIF avant la préparation. La présence d’un NIF sans routage bloque explicitement le lot ; aucun service n’est inventé. Enregistrer l’envoi après expédition effective. Dans Règles, renseigner le budget à partir de son approbation réelle.

`LETTERS_AUTOMATION_USERNAME` permet de choisir un compte superviseur dédié et actif. À défaut, le compte administrateur configuré est utilisé. Le lundi à 07 h de Kinshasa, les courriers sont préparés ; le rapport hebdomadaire suit à 07 h 05 ; la note mensuelle est archivée le premier du mois à 07 h 10. La plateforme doit rester démarrée, le compte habilité et le routage complet. `LETTERS_CRON` permet d’adapter le créneau des courriers.

Les migrations V38 à V43 ont été appliquées à la base de recette puis à la base locale de travail, après sauvegarde PostgreSQL. Cette recette ne démontre pas leur déploiement en production.

## Limites de réception

Les nouvelles API de consultation et de retour SITAX/FACNO, les coordonnées et demandes saisies dans l’application citoyenne, les notifications et la gateway nécessitent encore leurs contrats et leur recette fournisseur. Les dimensions province/ville/service des indicateurs dépendent de données qui ne sont pas fournies actuellement ; le routage des courriers ne remplace pas ces données fiscales.

La détection automatique des retouches et la mesure de qualité OCR sur des pièces réelles variées ne sont pas validées. La phase 1 conserve la revue humaine décrite dans les décisions du 7 novembre. La formation, la remise administrative, l’exploitation des sauvegardes hors serveur et la recette sur réseau lent restent des vérifications d’exploitation distinctes.
